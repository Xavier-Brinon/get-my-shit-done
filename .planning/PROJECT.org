* GMSD (Get My Shit Done)

** What This Is

A customised fork of Get Shit Done (GSD) — a meta-prompting, context engineering, and spec-driven development system for Claude Code. GMSD reshapes GSD to fit a specific workflow: Emacs/Org-mode as the documentation format, Architecture Decision Records baked into the planning process, and a "learn software architecture" lens on the existing spec-driven development system. Every document GMSD produces is classified by Diataxis quadrant (tutorial, how-to, reference, or explanation).

** Core Value

Every document GMSD produces — both its own internal docs and the deliverables it generates for user projects — follows a principled documentation framework so users always find the right type of doc for their need.

** Key Decisions

| Decision                                             | Rationale                                                                   | Outcome    |
|------------------------------------------------------+-----------------------------------------------------------------------------+------------|
| Diataxis as documentation framework                  | Well-established, maps cleanly to GMSD's two-layer doc system               | ✓ Good     |
| Classify + enforce (not restructure dirs)            | Directory restructuring adds user-facing complexity; classification in templates/agents is invisible | ✓ Good |
| Split USER-GUIDE rather than rewrite                 | Preserves existing content; reorganizes by quadrant                          | ✓ Good     |
| Dual-document reference pattern (.org + condensed .md) | Full authoritative .org + compact .md for agent tags; matches org-styleguide pattern | ✓ Good |
| Flat four-heading structure for diataxis.org         | Prioritises direct quadrant lookup over taxonomic browsing                   | ✓ Good     |
| =<diataxis_style>= tag pattern for agents            | Place after =</org_style>=, 15-22 lines, anti-patterns, ref condensed doc   | ✓ Good     |
| Tutorial skeleton scoped to GMSD workflow             | Concrete GMSD onboarding journey (discuss/plan/execute) over generic tutorial | ✓ Good |
| How-to skeleton kept generic                          | Usable for any multi-step procedure, not locked to GMSD                      | ✓ Good     |
| Retroactive verification with disk evidence           | Checks actual files and git log, not SUMMARY text alone                      | ✓ Good     |
| README.org as tutorial hub (not reference)            | Core workflow table retained; full tables moved to docs/reference.org         | ✓ Good     |
| Facade pattern for beautiful-mermaid                  | Single integration point (render-mermaid.cjs); no direct library calls       | ✓ Good     |
| Dynamic import() for ESM-only packages from CJS       | Avoids project-wide ESM migration; async but contained to Facade            | ✓ Good     |
| EXAMPLE+:exports none as canonical diagram pattern     | Pre-rendered ASCII visible to agents; Mermaid source preserved for re-render | ✓ Good     |
| Lowercase #+begin_example standardization              | Resolved styleguide contradiction; org-mode is case-insensitive anyway       | ✓ Good     |
