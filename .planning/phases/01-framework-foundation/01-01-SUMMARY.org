** Decisions Made

- *Flat four-heading structure:* Each quadrant is a top-level heading, not
  grouped by axis (practical/theoretical). Prioritises direct quadrant lookup
  (reader knows which quadrant they want) over taxonomic browsing (reader
  browses by axis). Trade-off: loses 2x2 navigation grouping, gains simpler
  document hierarchy. Per plan specification.
- *Markdown for condensed reference:* Matches the proven =org-styleguide.md=
  pattern. Condensed files are designed for agent =@=-reference tags; markdown
  is lighter to embed and renders well in tool contexts.
- *Anti-pattern format in full reference:* Warning + Test + Fix triple gives
  agents enough information to detect /and/ correct misclassification, not just
  recognise it. The test question helps distinguish boundary cases.
- *Mermaid decision tree with text fallback:* Mermaid for Emacs =ob-mermaid=
  rendering; text numbered list ensures the decision logic is available without
  diagram rendering.

** Architectural Observations

- *Emergent patterns:* The dual-document reference pattern (full .org +
  condensed .md) is now established for the second time (after org-styleguide).
  This pattern should be codified as a GMSD convention: any framework reference
  that agents need to consume should produce both forms. Common Closure
  Principle — changes to the framework are expressed in the full reference and
  propagated to the condensed reference.
- *Coupling discovered:* The condensed reference must stay in sync with the
  full reference manually. No automated consistency check exists. If Diataxis
  definitions change, both files must be updated. This is acceptable given the
  low frequency of framework changes, but worth noting as a maintenance
  dependency.
- *Boundary assessment:* The decision to keep classification logic (decision
  tree, disambiguation) in the reference document rather than a separate
  classification guide is correct for Phase 1. Phase 2 will implement
  classification workflows that /use/ this reference rather than embedding
  their own definitions.
- *ADR candidates:* "Dual-document reference as GMSD convention for consumable
  framework references" — could warrant an ADR if a third reference document
  follows this pattern (hat-trick = pattern, not coincidence).
