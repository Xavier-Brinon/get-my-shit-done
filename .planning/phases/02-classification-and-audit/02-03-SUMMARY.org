** Architectural Observations

- *Emergent patterns:* The audit reveals that GMSD is structurally a
  reference-first system — every phase of documentation output is optimised
  for fact lookup. This is architecturally sound for an AI workflow tool where
  agents need to retrieve specific state, not read narrative. The Diataxis
  framework makes this explicit: GMSD's documentation architecture is a
  reference warehouse with one explanation gateway (=project.org=), one
  how-to onramp (=user-setup.org=), and no tutorial entry point.
- *Coupling discovered:* The three summary variant templates
  (=summary-complex=, =summary-standard=, =summary-minimal=) all classify
  identically (reference, no secondary, no meta). This shared classification
  is intentional — they are structural variants of the same document type.
  If the classification changes, it must change in all three simultaneously.
- *Boundary assessment:* The Tutorial/How-to boundary is the most critical
  architectural gap. The existing =user-setup.org= (How-to) gets closest to
  tutorial territory but is scoped to external service configuration, not
  learning. A Tutorial template must explicitly foreground learning as its
  success criterion, not task completion.
- *ADR candidates:* The decision to classify GMSD's reference dominance as
  intentional rather than a structural problem may warrant an ADR. The
  principle at stake: "GMSD templates should optimise for agent fact-retrieval
  (reference) rather than human learning (tutorial/explanation)." If this
  principle is ever challenged (e.g., for a user-facing documentation
  system), the ADR would record why reference dominance was chosen.
