** Decisions Made

- *Tutorial skeleton scoped to GMSD* (discuss-phase / plan-phase /
  execute-phase cycle): the tutorial must demonstrate a complete, working
  GMSD cycle to be genuinely useful for onboarding
- *How-to skeleton kept generic*: the template must be usable for GMSD
  workflows, deployment runbooks, and operational guides — GMSD-specific
  framing belongs in the examples, not the skeleton
- *Good examples may be GMSD-specific*: examples are illustrative, not
  prescriptive; a GMSD-specific worked example demonstrates the template
  better than a fabricated generic one
- *Org comments throughout*: all guidance text uses org comment syntax
  so it is visible when editing but invisible when exported — consistent
  with the project.org comment pattern
