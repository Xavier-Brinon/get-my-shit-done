** Architectural Observations

- *Emergent patterns:* The =reference-only= content rule for =references/= is
  an architectural invariant: the agent knowledge base exclusively serves the
  consulted-not-read use case. This is the Common Closure Principle applied
  to documentation directories — files that change for the same reason
  (agents needing lookup facts) belong together, and the directory label
  enforces the constraint.
- *Coupling discovered:* Two-location file management (project source +
  installed copy) creates a synchronisation obligation. Changes to
  =references/= files must be applied in both places. This is a known
  trade-off of the install model; the project source is the source of truth,
  the installed copy is the runtime copy.
- *Boundary assessment:* The distinction between org files (PROPERTIES drawer
  under first heading) and markdown files (YAML frontmatter at top) reflects
  the correct format boundary — each format's metadata convention is
  respected without forcing uniformity.
- *ADR candidates:* None from this plan. The metadata format choices (YAML
  for md, PROPERTIES for org) were decided in earlier phases.
