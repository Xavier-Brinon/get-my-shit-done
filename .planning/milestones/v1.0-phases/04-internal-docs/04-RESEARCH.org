** Summary

Phase 4 is a documentation restructuring phase with no code changes and no
external library dependencies. The domain is entirely internal: Org-mode file
editing, Diataxis quadrant application, and cross-document linking.

All prior phases established the necessary preconditions. Phase 1 defined the
=:diataxis_primary:= property pattern and the condensed reference in
=references/diataxis-condensed.md=. Phase 2 applied that pattern to all 38
templates. Phase 4 applies the same established pattern to three artifacts that
remained unclassified: =USER-GUIDE.org= (which is split rather than merely
classified), =references/= files (metadata-only classification), and =README.org=
(restructured as an onboarding hub).

The primary risk is content allocation judgment: some USER-GUIDE.org sections
sit on the how-to/reference boundary. The how-to quadrant governs step-oriented
goal accomplishment; the reference quadrant governs fact lookup. The distinction
is reliable for the sections audited below.

*Primary recommendation:* Execute as three parallel plans (DOCS-01, DOCS-02,
DOCS-03). All three are independent — none modifies files touched by the others.
DOCS-01 touches =docs/=; DOCS-02 touches =references/=; DOCS-03 touches
=README.org=. Wave 1 can run all three in parallel.

*** Pattern 1: Diataxis property drawer (established)

The =:diataxis_primary:= property drawer pattern was established in Phase 2.
Apply identically here. Org files receive a file-level property drawer; =.md=
files receive a YAML frontmatter block.

Org file pattern:

#+begin_src org
:PROPERTIES:
:diataxis_primary: reference
:diataxis_secondary: none
:diataxis_rationale: Reader looks up [what the reader looks up]
:END:
#+end_src

Markdown file pattern:

#+begin_src yaml
---
diataxis_primary: reference
diataxis_secondary: none
diataxis_rationale: Reader looks up [what the reader looks up]
---
#+end_src

*** Pattern 2: Nav header in docs/ files

Every file in =docs/= (including the two new files) gets a consistent nav
header in italics using native org links. This is a Claude's Discretion area
for exact styling and placement. The locked decision specifies the form:

#+begin_src org
/Navigation: [[../README.org][Home]] | [[howto.org][How-to]] | [[reference.org][Reference]]/
#+end_src

Placement: immediately after the =#+options:= header line, before the first
heading. A horizontal rule (=-----=) separates it from the body.

*** Pattern 3: README as onboarding hub

The restructured README retains the "Why" explanation sections but removes the
dense command tables and full configuration schema, which move to
=docs/reference.org=. The README's new role is a tutorial-quadrant entry point:
the reader follows it to get from zero to running GMSD.

Links from README to =docs/= files use org file links:

#+begin_src org
For the full command reference, see [[file:docs/reference.org][User Guide — Reference]].
For workflow procedures and troubleshooting, see [[file:docs/howto.org][User Guide — How-to]].
#+end_src

*** Anti-Patterns to Avoid

- *Splitting on topic rather than quadrant:* The boundary between the two new
  files is quadrant (goal-oriented steps vs fact lookup), not topic area. A
  command table is reference even if it describes a workflow command; a
  step-by-step recovery procedure is how-to even if it's about configuration.
- *Leaving README with both tutorial and reference content:* The current README
  mixes "Getting started" (tutorial) with "Commands" and "Configuration"
  (reference). The restructured README must remove or link out the reference
  sections to achieve a clean tutorial classification.
- *Adding redirect stubs:* Locked decision — delete =USER-GUIDE.org=, no stub.
- *Moving =references/= files:* Path stability is a locked constraint. Only
  add metadata; never rename or move files in =references/=.

** Common Pitfalls

*** Pitfall 1: Breaking agent @file references

*What goes wrong:* Moving or renaming any file in =references/= breaks agent
system prompts that use =@file= paths. For example,
=@/Users/xavierbrinon/.claude/get-my-shit-done/references/diataxis-condensed.md=
is embedded in 7 agent files. A rename silently breaks those agents.

*Why it happens:* The user path for =references/= is in the global Claude install
(=~/.claude/get-my-shit-done/references/=), not the project repo. Agents use
absolute paths baked into their system prompts.

*How to avoid:* Locked decision — metadata only, no restructure. Verify by
grepping agent files for =@file= references before any file modification.

*Warning signs:* Any proposed task that involves =mv=, =rename=, or new directory
creation in =references/=.

*** Pitfall 2: Property drawer placement in file-level frontmatter

*What goes wrong:* For SUMMARY, PLAN, and VERIFICATION files, the GMSD
convention places the property drawer at the very top of the file (before the
first heading). For general documents being classified here, the drawer belongs
under the first heading, not at file-level.

*Why it happens:* The org-styleguide.md has two drawer placement rules — file-
level (for GMSD-parsed files) and heading-level (for general docs). Confusion
causes drawers to be misplaced.

*How to avoid:* =docs/= files and =references/= files are general documents, not
GMSD-parsed frontmatter files. Use heading-level drawers: the =:PROPERTIES:=
drawer goes under the first heading (=* Title=), not at file top.

*Warning signs:* A drawer appearing before =* Title= in files that are not PLAN,
SUMMARY, or VERIFICATION.

*** Pitfall 3: Orphaned links after USER-GUIDE.org deletion

*What goes wrong:* =README.org= currently contains a link to =USER-GUIDE.org=
(line 579: =[[file:docs/USER-GUIDE.org][User Guide]]=). Deleting =USER-GUIDE.org=
without updating README creates a broken org link.

*Why it happens:* DOCS-01 (split + delete) and DOCS-03 (README restructure) are
independent plans that both touch the same link relationship.

*How to avoid:* DOCS-03 (README restructure) must update all links to
=USER-GUIDE.org= to point to the new =docs/reference.org= and =docs/howto.org=.
If run in parallel, DOCS-03 must know the final filenames from DOCS-01. Since
the filenames are locked decisions, parallel execution is safe — the executor
for DOCS-03 can reference the locked filenames without waiting for DOCS-01.

*Warning signs:* Any =[[file:docs/USER-GUIDE.org]]= link remaining in any file
after phase completion.

*** Pitfall 4: Over-emptying README

*What goes wrong:* In zealous pursuit of a "clean tutorial quadrant" README, too
much content is removed, leaving the README too sparse to be useful as an
onboarding hub. The Commands section is reference, but a brief command table is
valuable for first-time readers.

*Why it happens:* The Diataxis rule "tutorial = learning-oriented" is interpreted
as "remove all reference material," but a good tutorial includes enough reference
context for the reader to act.

*How to avoid:* The audit table above identifies what stays vs moves. "Brief"
retention is the pattern for commands and configuration: keep enough for quick
reference, link to =docs/reference.org= for the full schema. The Commands section
in README is shorter than the User Guide's Command Reference, and that difference
is intentional.
