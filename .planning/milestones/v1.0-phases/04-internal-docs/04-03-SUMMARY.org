** Architectural Observations

- *Emergent patterns:* The README naturally fell into the tutorial/explanation
  split that Diataxis predicts — introductory narrative (tutorial), "Why"
  sections (explanation), and command/config tables (reference) each belong to
  distinct quadrants. The refactor confirmed that mixed-quadrant documents are
  the problem, not a structural limitation of the README format.
- *Coupling discovered:* README links to both =docs/reference.org= and
  =docs/howto.org= are forward-links to files created in Plans 04-01 and 04-02.
  This means README depends on those files existing; the dependency is now
  expressed as org file links rather than inline tables.
- *Boundary assessment:* The tutorial/reference boundary in the Commands section
  is subtle — a "core workflow table" sits at the boundary of tutorial and
  reference. The decision to keep it in README (tutorial) is correct: first-time
  readers need actionable commands immediately, not just narrative. Full
  reference belongs in docs/reference.org (Reference quadrant). The retained
  table is context, not a catalogue.
- *ADR candidates:* None — the decision to retain core workflow table in README
  follows the established Diataxis anti-pattern guidance already documented in
  RESEARCH.org (Pitfall 4: over-emptying).
