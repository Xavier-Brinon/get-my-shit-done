** Decisions Made

- *reference dominance:* 34 of 36 templates classified as reference
  primary. GMSD templates generate documents that agents and developers
  consult for specific facts — the classic reference use case.
- *project.org as explanation:* The generated PROJECT.org is not a
  lookup document — it answers "what is this project and why?" for
  readers building a mental model before engaging with plans.
- *user-setup.org as how-to:* The generated USER-SETUP.org is a
  task-completion guide — the reader has a specific goal (configure
  Stripe) and follows numbered steps. This is the canonical how-to
  pattern.
- *adr.org as reference/explanation:* The ADR itself is a reference
  fact (what was decided), but the Pros and Cons sections provide
  explanatory discussion. Secondary: explanation.
- *research.org as reference/explanation:* Research documents are
  primarily consulted for stack recommendations and pitfalls
  (reference), but the "why standard" rationale columns and pitfall
  explanations are explanatory. Secondary: explanation.
- *7 meta templates:* continue-here, debug-subagent-prompt, DEBUG,
  UAT, phase-prompt, planner-subagent-prompt, VALIDATION are tagged
  =:diataxis_meta: true= — internal machinery, not user-facing output.

** Architectural Observations

- *Emergent patterns:* Reference dominates overwhelmingly (34/36).
  GMSD's template architecture reflects the Diataxis principle that
  reference material is the backbone of a technical system's
  documentation — every codebase map, research finding, and execution
  state document is consulted, not read linearly.
- *Coupling discovered:* The three summary variant files
  (summary-complex, summary-standard, summary-minimal) share identical
  diataxis classification — they are structural variants of the same
  document type. This is intentional coupling (same purpose, different
  depth), but worth noting: if the classification ever needs to change,
  it must change in all three.
- *Boundary assessment:* The how-to/reference boundary was cleanest at
  =user-setup.org= — it is the only template whose generated output
  directs a human to accomplish a task step-by-step. All other
  templates generate lookup/consultation documents.
- *ADR candidates:* The =project.org= classification as =explanation=
  rather than =reference= is a subtle but important boundary decision.
  The distinction: PROJECT.org answers "what is this and why?" (builds
  mental model), while ROADMAP.org answers "what phases are planned?"
  (looks up specifics). This aligns with Diataxis's explanation vs
  reference separation and may warrant an ADR if the classification is
  ever challenged.
