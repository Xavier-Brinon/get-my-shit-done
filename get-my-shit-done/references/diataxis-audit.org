** Gap Analysis

Analysis of underserved quadrants in deliverable templates (29 total).

*** Tutorial (CRITICAL GAP — 0 deliverable templates)

- *Current count:* 0 deliverable templates
- *Gap severity:* Critical — zero coverage
- *User need unserved:* A new GMSD user has no guided, learning-oriented entry
  point. Tutorials are for beginners who need to build confidence through a
  structured, success-guaranteed experience. Without a tutorial template, GMSD
  has no mechanism to onboard users into the workflow — they must discover how
  to use the system through reference documents, which assumes prior knowledge.
- *Concrete absence:* No "Getting Started" or "Your First Plan" guided walkthrough
  template exists. A new user cannot follow a worked example that builds
  understanding incrementally.
- *Requirement:* GAPS-02 (create tutorial template for Tutorial quadrant)

*** Explanation (LOW COVERAGE — 1 deliverable template)

- *Current count:* 1 deliverable template (=project.org=)
- *Gap severity:* Low — coverage exists but is minimal
- *User need underserved:* Explanation documents answer "why?" and build mental
  models. Only =project.org= serves this purpose. The GMSD system itself has no
  explanation document — there is no template for writing "why this architecture
  decision was made" beyond =adr.org= (which is primarily reference). Users who
  want to understand the /rationale/ behind their project's choices have only the
  ADR template, which is structured as a decision record, not a conceptual guide.
- *Concrete absence:* No template for architectural concept documents, design
  rationale summaries, or system-level explanation writing exists beyond
  =project.org=.

*** How-to (LOW COVERAGE — 1 deliverable template)

- *Current count:* 1 deliverable template (=user-setup.org=)
- *Gap severity:* Low — coverage exists but is scoped only to service configuration
- *User need underserved:* How-to documents guide a reader through accomplishing
  a specific goal. Only =user-setup.org= serves this purpose, and it is scoped
  exclusively to configuring external services (Stripe, AWS, etc.). There is no
  how-to template for GMSD workflow steps themselves — no "how to run a phase",
  "how to add a template", or similar operational guides.
- *Concrete absence:* No general-purpose how-to template exists for documenting
  repeatable multi-step procedures beyond external service configuration.
- *Requirement:* GAPS-03 (create how-to template for How-to quadrant)

*** Reference (WELL SERVED — 27 deliverable templates)

- *Current count:* 27 deliverable templates
- *Gap severity:* None — dominant quadrant
- *Note:* Reference coverage is intentional. GMSD templates generate documents
  that agents and developers consult for specific facts. The consulted-not-read
  pattern is the correct use case for the vast majority of GMSD outputs.

** Misalignment Summary

No templates classified as =:diataxis_misaligned: true= in Plan 02-01.

All 36 templates were assessed against the Diataxis decision tree:
- Does the reader look up specific facts? → Reference
- Does the reader follow steps to accomplish a goal? → How-to
- Does the reader build understanding of a concept? → Explanation
- Does the reader complete a guided learning exercise? → Tutorial

No template's content was found to contradict its assigned primary quadrant.
The planned pre-assessment in 02-01-PLAN.org (all codebase and research-project
templates as reference) was confirmed correct for all 12 templates in that group.

*No misalignment corrections are required.*

** Recommendations for Phase 3

Based on gap analysis, the following recommendations are ordered by severity:
zero-coverage quadrants take priority over low-coverage quadrants.

*** Priority 1: Create Tutorial Template (GAPS-02)

- *Quadrant:* Tutorial (0 deliverable templates — critical gap)
- *Recommended template:* =templates/tutorial.org=
- *Content:* A structured, success-guaranteed walkthrough that takes a new user
  through one complete GMSD workflow from start to finish. The tutorial must:
  - Have a clear, achievable end state ("you will have a committed plan")
  - Present steps in sequence with no branching decisions for the learner
  - Be encouraging and congratulatory at completion
  - Not require prior GMSD knowledge
- *Structural model:* =user-setup.org= provides the closest model (step-by-step,
  goal-oriented) but Tutorial differs from How-to in one critical dimension:
  Tutorial is for learning, not for getting something done. Steps in a tutorial
  are chosen to build understanding, not for efficiency.
- *Suggested scope:* "Your First GMSD Phase" — guides a new user through running
  =gmsd:discuss-phase=, reading the generated ROADMAP.org, and executing one plan.
- *Connects to:* GAPS-02 requirement

*** Priority 2: Create How-to Template for Repeatable Procedures (GAPS-03)

- *Quadrant:* How-to (1 deliverable template — low coverage)
- *Recommended template:* =templates/howto.org= (general-purpose how-to guide)
- *Content:* A template for documenting any repeatable multi-step procedure with
  a specific goal. Unlike =user-setup.org= (scoped to external service
  configuration), this template should be generic enough for workflow
  documentation, runbook entries, and operational procedures.
- *Structural model:* =user-setup.org= is the direct model — numbered steps,
  goal statement, verification commands. The new template removes the
  "external service" framing and makes the goal and steps generic.
- *Suggested scope:* Generic how-to guide usable for any operational procedure
  a GMSD project team needs to document.
- *Connects to:* GAPS-03 requirement

*** Priority 3: Evaluate Explanation Coverage (No Requirement Yet)

- *Quadrant:* Explanation (1 deliverable template — low coverage)
- *Status:* No formal requirement exists yet; assess after GAPS-02 and GAPS-03
- *Observation:* The single explanation template (=project.org=) serves its
  purpose well — PROJECT.org is the correct place for "what is this project and
  why?" writing. The gap is real but lower urgency than Tutorial and How-to
  because explanatory content can be embedded in ADRs (=adr.org= secondary:
  explanation) and RESEARCH.org (=research.org= secondary: explanation).
- *Future consideration:* If GMSD projects regularly need standalone conceptual
  guides (architecture overview documents, design rationale documents), a
  dedicated explanation template for those use cases would address the gap.
  Consider as Phase 4 scope.
